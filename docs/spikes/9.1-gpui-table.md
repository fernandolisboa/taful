# Spike §9.1 — GPUI table render on Windows

Goal (brief §9.1): draw a poker table with seats, chips and cards, plus a drag-and-drop panel, on Windows, with GPUI.

## What the spike renders

`apps/desktop` (binary `taful`), GPUI `0.2.2` from crates.io:

- Oval table (rail + felt), 6 seats placed on an ellipse, avatars, stacks, positions, folded seats dimmed.
- Board (4 cards, one of each suit, to check the 4-color deck), hero hole cards, villain card backs.
- Chip stacks, pot label, bet in front of the bettor, dealer button.
- Action buttons with hover and click (the footer shows the last action).
- A panel dragged by its header. It follows the cursor freely; a dot grid and a dashed outline of the landing spot show while dragging, and it **snaps to the 24 px grid on release** (hold Alt to drop without snapping). This is the primitive the layout editor (D7) builds on.
- Default theme from tokens (`theme.rs`): petrol-teal felt, amber/gold accents, cream type, no red.

Throwaway code. The real app structure comes from the spec.

## How to get it

CI (`.github/workflows/desktop-windows.yml`) builds on `windows-latest`, runs the app for ~15 s, takes a screenshot of the runner desktop, and uploads two artifacts:

- `taful-windows-x64` — `taful.exe` (release build, unsigned)
- `screenshot-windows` — `screenshot.png` + app logs

Download them from the workflow run page (Summary → Artifacts). `taful.exe` is unsigned, so SmartScreen may ask: "More info → Run anyway".

Or build locally on Windows: `cargo run --release -p taful-desktop` (needs Rust stable + MSVC build tools + Windows SDK).

## What to check on a real Windows machine

1. Window opens; nothing is cut off at your resolution / DPI scaling (try 100 % and 150 %).
2. Text is crisp; suit symbols ♠ ♥ ♦ ♣ render (not boxes).
3. The 4 suit colors are easy to tell apart, especially ♥ (burnt orange) vs ♦ (gold).
4. Dragging the panel is smooth, and it snaps to the grid only on release; resizing the window keeps the table centered.
5. Buttons react to hover and click.
6. Idle CPU/GPU usage in Task Manager stays low.

## Known issues

- Linux/macOS builds currently fail: `gpui 0.2.2` pulls `xattr 0.2.3`, which does not compile with `libc >= 0.2.182` (`ENOATTR` removed). Windows is unaffected. Fix when we move to a newer GPUI (git) or a patched `xattr`.
- On Linux/Xvfb (software Vulkan) the first frame only appeared after a mouse move; not yet seen on Windows.
